# Data model

This document explains how the Monserrate funicular and cable car are represented in GTFS, and which assumptions were made where the operator's website gives no information.

## Agency

| Field | Value |
|---|---|
| `agency_id` | `TAM` |
| Name | Teleférico a Monserrate S.A. |
| Timezone | `America/Bogota` |
| Language | `es` |

## Stops

Each end of the line is a parent station (`location_type=1`) with two platforms: one for the funicular and one for the cable car. The platforms sit in separate buildings at the summit, and in one shared building at the bottom.

| `stop_id` | Type | Parent | Source |
|---|---|---|---|
| `ABAJO` | station | – | midpoint between both lower platforms (building: OSM way 58868758) |
| `FUN_ABAJO` | platform | `ABAJO` | OSM node 12536828938 |
| `TEL_ABAJO` | platform | `ABAJO` | OSM node 12536828937 |
| `CUMBRE` | station | – | midpoint between both summit stations |
| `FUN_CUMBRE` | platform | `CUMBRE` | OSM node 1005395546 |
| `TEL_CUMBRE` | platform | `CUMBRE` | OSM node 1151938687 |

The OSM node id of each platform is in the table above and in a comment in `build.py`. `stop_code` and `platform_code` are left empty: journey planners show them to passengers (Digitransit shows the stop code under the stop name and the platform code inside the stop marker on the map), so an OSM id or a word like "Teleférico" does not belong there.

## Routes and shapes

| `route_id` | Name | `route_type` | OSM ways used for the shape |
|---|---|---|---|
| `FUN` | Funicular de Monserrate | 7 | 99625017, 99625025 (tunnel), 28555379 |
| `TEL` | Teleférico de Monserrate | 6 | 360392328 |

Each route has an `_UP` shape and a `_DOWN` shape, with `shape_dist_traveled` in metres.

## Services (calendar)

There are three service types per route, so six `service_id`s in total:

| `service_id` suffix | Active on | Defined in |
|---|---|---|
| `_MO_SA` | Monday–Saturday | `calendar.txt` |
| `_SUNDAY` | Sunday | `calendar.txt` |
| `_HOLIDAY` | Colombian public holidays | `calendar_dates.txt` only |

Rules applied in `calendar_dates.txt`:

1. **Holiday on Mon–Sat.** `_MO_SA` is removed and `_HOLIDAY` is added.
2. **Holiday on a Sunday.** Regular Sunday service runs; nothing changes.
3. **Temporary suspension** (`SUSPENSIONS` in `build.py`). All services of that route are removed for the given dates. This overrides rule 1.

Holidays come from the `holidays` package (`holidays.Colombia`), which handles the *Ley Emiliani* Monday shifts and the moveable Easter dates.

## Trips, stop times and frequencies

Each service type and direction has one template trip with two stops. Departures are generated by `frequencies.txt`:

| Service | Start | End | Note |
|---|---|---|---|
| Mon–Sat | 06:30 | 22:00 | |
| Sunday | 05:30 | 17:00 | |
| Holiday | 06:30 | 17:00 | |
| Mon–Sat, funicular down only | 05:30 | 06:30 | early descent for athletes (`FUN_MO_SA_DOWN_EARLY`) |

- **`exact_times=0`.** The operator runs continuously without a published timetable, so departures are not exact.
- **Last departure.** The website says the last car departs at closing time. To make the final departure fall *on* closing time, `end_time` is set to closing time plus one second.

### Assumptions

These values are **not** published by the operator.

| Parameter | Value | Basis |
|---|---|---|
| Headway (`HEADWAY_SECS`) | 15 min | estimate |
| Funicular ride time | 4 min | estimate |
| Cable car ride time | 5 min | OSM tag `aerialway:duration=5` |
| Which line runs when | both lines, all opening hours | the website only says "funicular and/or cable car" |
| Athlete descent | runs on the funicular | not specified on the website |
| Wheelchair access | `0` (unknown) | not specified |

If better information becomes available, adjust the constants in `build.py`.

## Transfers

`transfers.txt` allows changing between funicular and cable car at the same station. Both directions at both stations are included, with `transfer_type=2` and a minimum transfer time of 3 minutes.

## Fares (GTFS Fares v2)

Prices differ between Mon–Sat/holidays and Sundays. This is modelled with timeframes:

- `timeframes.txt` defines two groups:
  - `WEEK`: the `_MO_SA` and `_HOLIDAY` services
  - `SUN`: the `_SUNDAY` services
- `fare_leg_rules.txt` links every product to the `MONSERRATE` network and to its timeframe group.
- `networks.txt` and `route_networks.txt` put both routes in the `MONSERRATE` network.

| `fare_product_id` | Name | COP |
|---|---|---|
| `one_way_week` | Un trayecto (lun–sáb y festivos) | 21,000 |
| `round_trip_week` | Ida y regreso (lun–sáb y festivos) | 35,000 |
| `senior_week` | Adulto mayor 62+ (lun–sáb y festivos) | 29,500 |
| `fast_pass_week` | Fast pass (lun–sáb y festivos) | 96,500 |
| `round_trip_sun` | Ida y regreso (domingo) | 21,000 |
| `senior_sun` | Adulto mayor 62+ (domingo) | 16,500 |
| `fast_pass_sun` | Fast pass (domingo) | 96,500 |

Limitations:

- **Round trips.** GTFS cannot express a return ticket well. Round-trip products are attached to a single leg, and consumers will show them as one of the options for that leg.
- **Senior fares.** They are separate products, not rider categories.
- **Fares left out.** Group fares, pet fares, extra-item fares and athlete fares are not included.
- **Sunday one-way.** The website lists no Sunday one-way fare, so none is included.

## Not included

- The Paramuno trail and the pedestrian path, which are not public transport.
- The basilica and Eucharist times.
- Real-time information.
